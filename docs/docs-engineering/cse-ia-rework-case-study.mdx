# Cloud Secure Edge information architecture

<p className="hub-sub">I reorganized the Cloud Secure Edge docs around the tasks people actually come to do. The new structure is live, and every existing link still works.</p>

<div className="ctx-prose">
  <p className="ctx-label">Background</p>
  <p>Cloud Secure Edge is a SonicWall service that decides whether an employee’s device can connect to a company’s apps and websites. Its docs site serves admins at every stage: evaluating the product, deploying it, running it day to day, and fixing things when they break.</p>
  <p>The site’s navigation followed the way the product is engineered, so you had to understand its internal components before you could find the task you came for. I designed a new structure around those tasks, rewrote the navigation labels, and redesigned the docs homepage.</p>
</div>


<div className="ia-brief">
  <div><h4>Problem</h4><p>The navigation was organized by product component, but people show up with a task.</p></div>
  <div><h4>Constraint</h4><p>Everything had to happen in the navigation. No page could move and no URL could change, so bookmarks, search results, and links from support articles all kept working.</p></div>
  <div><h4>What I tried</h4><p>[An approach you considered and dropped.]</p></div>
  <div><h4>The outcome</h4><p>Tasks now live under names that describe the work, in the order an admin does it. [Add a reader signal.]</p></div>
</div>
