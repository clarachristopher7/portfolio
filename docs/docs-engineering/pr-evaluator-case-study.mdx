# Documentation impact evaluator

<p className="hub-sub">A scheduled job compares recent code changes with the docs. It reports the pages that the changes probably made wrong, and a writer decides what to change.</p>

<div className="ctx-prose">
  <p className="ctx-label">Background</p>
  <p>Cloud Secure Edge is a service that decides whether an employee's device can connect to company apps and websites. Its engineers change the product every day, and its docs describe how the product works.</p>
  <p>I designed and built a scheduled job that tells the docs team which of those changes affect the docs.</p>
</div>

## The problem

When a change affects a feature that a docs page describes, the page becomes wrong. Nothing in the release process tells the docs team.

<div className="lanes">
  <div className="lane">
    <p className="arch-head">A product change, without the evaluator</p>

      <div className="arch-node"><b>An engineer merges a change</b></div>

    </div>
  </div>
</div>

Reading every code change by hand isn't realistic. Most changes never affect the docs, and the ones that do are hard to spot among them.

## The approach

Each run of the job follows four steps.

<ol className="ia-steps ia-steps--4" aria-label="How the evaluator works">
  <li>Read recent code changes</li>
  <li className="is-new">Check which changes are live<small>Key step</small></li>
  <li>Compare each change with the docs</li>
  <li>Write a dated report</li>
</ol>

Claude compares each change with an index of every docs page. The report lists the pages that probably need an update.

Two lessons changed how the job works.

  <div className="chain chain--3"><div className="arch-node arch-node--old"><b>The first version read the testing copy of the code</b></div><div className="arch-node"><b>It found one of the nine changes in a release</b><span>New features reach the main development code first</span></div><div className="arch-node arch-node--new"><b>The job now reads the main development code</b></div></div>

</div>

## The constraint

<div className="ts-steps">

1. I couldn't change how engineering releases the product.
2. The job had to work from what engineers already produce, the code changes in the repository, without adding a step to their process.

</div>

## The outcome

The job runs on a schedule and writes a dated report. A writer works through a short list of likely changes instead of reading every code change, and decides what to update.
