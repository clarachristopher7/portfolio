# Information architecture across a product portfolio

<p className="hub-sub">Documentation for each SonicWall product had developed independently. I built a model that assesses every product’s documentation against one definition of completeness, so gaps could be demonstrated with evidence.</p>

<dl className="ctx">
  <div><dt>The situation</dt><dd>SonicWall sells firewalls, cloud services, apps installed on employees’ computers, and portals for partner companies. Each has its own documentation, written in different tools by different teams, with no shared standard for what a complete set should contain.</dd></div>
  <div><dt>Who uses it</dt><dd>Documentation leads and product owners deciding where documentation effort should go.</dd></div>
  <div><dt>What they’re doing</dt><dd>Establishing which products are missing which content, in a way that is fair to products with very different needs.</dd></div>
  <div><dt>My part</dt><dd>I designed the model, the rules that assign each status, and the single-file tool that presents it.</dd></div>
</dl>


<div className="ia-brief">

## Fair to unlike products

A cloud service and a hardware appliance need different documentation. Each product is classified by type, and only the sections relevant to that type count toward its assessment, so a status means the same thing across the portfolio.

<p className="ia-chips"><span>Cloud service</span><span>Hardware appliance</span><span>Employee app</span><span>Partner portal</span><span>Shared content</span></p>
