# Information architecture across a product portfolio

<p className="hub-sub">Every SonicWall product’s docs had grown up on their own. I built a model that measures them all against the same definition of complete, so you can point to a gap and show the evidence for it.</p>

<div className="ctx-prose">
  <p className="ctx-label">Background</p>
  <p>SonicWall sells firewalls, cloud services, apps that run on employees’ computers, and portals for partner companies. Each product’s docs were written by a different team, in a different tool, with no shared idea of what a complete set should include. That made it hard for docs leads and product owners to see where the real gaps were, or decide where to focus.</p>
  <p>I designed a model that measures every product’s docs against the same standard, the rules that decide each status, and a single-page tool that shows the results.</p>
</div>


<div className="ia-brief">
  <div><h4>Problem</h4><p>Without a shared standard, coverage gaps came down to opinion, and you couldn’t compare one product with another.</p></div>
  <div><h4>Constraint</h4><p>It had to be one self-contained web page that anyone could open and any writer could keep up to date.</p></div>

## Fair to unlike products

A cloud service and a hardware appliance need different docs. So each product gets a type, and only the sections that make sense for that type count. That way, a status means the same thing no matter which product it’s on.

<p className="ia-chips"><span>Cloud service</span><span>Hardware appliance</span><span>Employee app</span><span>Partner portal</span><span>Shared content</span></p>
