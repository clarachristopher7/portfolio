# Documentation staleness auditor

<p className="hub-sub">The auditor compares the docs with each new version of the admin console. It produces a maintenance backlog in order of impact, so the team fixes the largest gaps first.</p>

<div className="ctx-prose">
  <p className="ctx-label">Background</p>
  <p>Cloud Secure Edge is a service that decides whether an employee's device can connect to company apps and websites. Admins set it up in a web-based admin console, and the docs walk them through each screen.</p>
  <p>I designed and built an auditor that checks the docs against each new version of that console.</p>
</div>

## The problem

New versions of the admin console ship often. A single release can change field labels, screenshots, and steps on many docs pages at the same time.

<div className="lanes">
  <div className="lane">
    <p className="arch-head">A console release, without the auditor</p>
    <div className="chain">
      <div className="arch-node"><b>A new console version ships</b></div>
      <div className="arch-node"><b>Labels, screenshots, and steps change on many pages</b></div>
      <div className="arch-node arch-node--old"><b>Manual reviews find the changes late</b></div>
      <div className="arch-node arch-node--old"><b>Customers find the mismatches first</b></div>
    </div>
  </div>
</div>

## The approach

The auditor runs after each console release.

<ol className="ia-steps ia-steps--3" aria-label="How the auditor works">
  <li>A new console version is released</li>
  <li>The auditor checks every page against it</li>
  <li className="is-new">A backlog ranked by impact<small>Output</small></li>
</ol>

It flags each page that no longer matches the console, says what changed, and ranks the pages by impact.

![A sample staleness backlog. Callouts point to the console version the docs were checked against, the column that says what no longer matches, and the impact ranking.](/img/automations/staleness-backlog-annotated.webp)

<p className="shot-cap">A sample backlog. The pages and changes are examples.</p>

## The constraint

<div className="ts-steps">

1. Console releases come often, and the docs team is small.
2. Each audit had to produce a backlog that the team could work through before the next release arrived.

</div>

## The outcome

Each console release now comes with a ranked backlog. The team fixes the largest gaps first, instead of finding them by chance or from customers. The first run flagged 41 pages, and 9 of them were high impact.
